# Web Copy 浏览器插件实现原理

## 1. 项目目标

Web Copy 是一个使用 TypeScript 开发的 Chrome Manifest V3 扩展。它允许用户在网页中通过鼠标选择一个 DOM 元素，将该元素及其子元素中的文字、HTML 结构、内联样式和图片保存到本地，并可同时生成 Markdown 文件。

插件不保存页面 JavaScript，也不下载外链 CSS。导出的目标是“内容可阅读、图片可离线访问”，而不是完整复制原网页的视觉效果和交互能力。

## 2. 整体架构

插件由三个主要运行环境组成：

```text
用户点击扩展图标
        ↓
后台 Service Worker
        ↓ 发送 START_SELECTION
网页 Content Script
        ↓ 选择、克隆并分析 DOM
后台 Service Worker
        ↓ 保存临时会话并打开导出页
扩展导出页
        ↓ 抓取/转换图片、清理 HTML、生成 Markdown
用户选择的本地目录
```

各部分职责如下：

- `src/content.ts`：运行在目标网页中，负责鼠标高亮、DOM 选择和资源扫描。
- `src/background.ts`：Manifest V3 后台 Service Worker，负责消息中转、保存会话、打开导出页以及跨域获取图片。
- `src/export.ts`：运行在扩展自己的导出页面中，负责配置界面、图片转换、文件生成和目录写入。
- `src/export-utils.ts`：HTML 清理、URL 修正、文件命名和资源地址替换等纯逻辑。
- `src/session-db.ts`：使用 IndexedDB 临时保存一次截取会话，避免把大量 HTML 和图片信息放入 URL。
- `src/types.ts`：定义截取会话、图片资源、导出配置和报告的数据结构。

## 3. DOM 区域选择

用户点击扩展图标后，后台向当前标签页发送 `START_SELECTION` 消息。Content Script 随后进入选择模式：

1. 将鼠标指针改成十字形。
2. 在捕获阶段监听 `mousemove`、`click` 和 `keydown`。
3. 鼠标经过元素时，通过 `getBoundingClientRect()` 获得元素位置和尺寸。
4. 使用一个 `position: fixed`、最高层级且不接收鼠标事件的覆盖层绘制蓝色边框。
5. 用户单击时阻止页面原有点击行为，将当前元素确定为导出根节点。
6. 用户按 Esc 时退出选择模式并移除覆盖层。

选择过程不会给原始元素添加 class 或修改其内容；高亮框是独立元素，因此退出后不会污染原网页 DOM。

## 4. DOM 克隆和资源扫描

确定区域后，插件使用 `cloneNode(true)` 深度克隆所选元素。后续清理和地址替换都发生在克隆副本中，不会改变用户正在浏览的页面。

插件同时遍历原节点与克隆节点：

- 对 `<img>`，优先读取浏览器已经选定的 `currentSrc`，再依次尝试 `src`、`data-src` 和 `data-original`，从而兼容 `<picture>`、`srcset` 和部分常见懒加载页面。
- 对 inline style，使用 `url(...)` 规则提取 `background-image` 等内联背景资源。
- 相对 URL 通过 `document.baseURI` 转换为绝对 URL。
- 当前接受 `http:`、`https:`、`file:` 和 `data:` 图片地址。
- 每项资源会获得一个内部 ID，并记录来源 URL、资源类型和原元素描述。

截取结果形成 `CaptureSession`，其中包含页面标题、页面 URL、截取时间、克隆后的 HTML 和资源清单。

## 5. 会话传递

Content Script 将 `CaptureSession` 发给后台。后台把会话写入扩展域的 IndexedDB，然后打开：

```text
export.html?session=<会话 ID>
```

导出页通过会话 ID 从 IndexedDB 读取数据。这样做有两个好处：

- 避免把可能很大的 HTML 放进查询参数或扩展消息中反复传递。
- 导出界面与原网页分离，不受原网站 CSS 和 JavaScript 干扰。

导出成功后会删除这条临时会话。

## 6. 图片获取与浏览器缓存

导出页逐项向后台发送 `FETCH_IMAGE` 请求。后台具有 `<all_urls>` host 权限，可以用 `fetch()` 读取多数跨域图片：

```ts
fetch(url, {
  cache: 'default',
  credentials: 'include',
  referrer: pageUrl,
});
```

其中：

- `cache: 'default'` 表示遵循正常 HTTP 缓存规则。若浏览器缓存仍然有效，网络栈可能直接复用缓存；否则会重新验证或下载。
- `credentials: 'include'` 会携带该资源域可用的凭据，便于获取需要登录状态的图片。
- `referrer` 尽量保留来源页面信息，但服务器防盗链、权限策略或响应头仍可能导致失败。

普通扩展没有一个通用、可靠的 API 可以直接读取 Chrome 磁盘缓存文件。因此这里的“避免重复下载”是让浏览器的 HTTP 缓存机制自行命中，而不是直接复制缓存目录中的二进制文件。

后台将响应读取为 Blob，再编码成 Data URL 返回导出页。导出页把 Data URL 恢复为 Blob 后进行转换或写盘。这个实现简单、消息结构稳定，但大图片会产生额外的 Base64 内存开销；如果以后处理大量超大图片，可以改为分块传输或在扩展页面直接抓取。

## 7. WebP 转换原理

当前插件可以把 JPEG、PNG 和 BMP 转成静态 WebP，完全在浏览器本地完成，不依赖服务器或 WASM：

```text
原始图片 Blob
    ↓ createImageBitmap()
浏览器解码后的像素
    ↓ CanvasRenderingContext2D.drawImage()
Canvas 像素
    ↓ canvas.toBlob('image/webp', 0.85)
WebP Blob
```

Chrome/Edge 内置了这些图片解码器和 WebP 编码器，所以插件只需调用 Web API。代码还会检查返回 Blob 的 MIME 类型是否确实为 `image/webp`，避免浏览器不支持目标格式时静默回退成 PNG。

Canvas 转换属于重新编码，通常不会保留 EXIF、ICC 等原始元数据。GIF、SVG、AVIF 以及其他未列入转换白名单的格式当前保持原文件：GIF 可能包含动画，SVG 是矢量格式，使用普通 Canvas 转换会丢失这些特性；动画 WebP、动画 AVIF 和 AVIF 输出也尚未实现。

## 8. HTML 清理和本地化

保存前，插件通过 `<template>` 解析克隆 HTML 并进行清理：

- 删除 `<script>`。
- 删除外链样式表 `<link rel="stylesheet">`。
- 删除所有 `on...` 事件属性，例如 `onclick`。
- 删除 `javascript:` URL。
- 删除 `srcset`，避免离线打开时浏览器重新选择远程图片。
- 把 `href`、`src`、`poster` 及 inline style 中的相对地址转换为绝对地址。
- 图片成功保存后，把对应地址替换为 `images/<文件名>`。
- 图片下载失败时保留原始远程或本地 URL，确保仍有机会在线显示。
- 删除用于资源映射的 `data-web-copy-resource` 内部标记。

最后把清理后的片段放入一个完整的 HTML5 文档，生成 `index.html`。由于不保存外链 CSS，页面布局和原站可能不同，但 DOM 结构、文字和 inline style 会尽量保留。

## 9. Markdown 生成

如果开启 Markdown 选项，插件使用 Turndown 将清理并完成图片地址替换后的 HTML 转为 Markdown。标题使用 ATX 风格，代码块使用 fenced 风格。

因为转换发生在图片本地化之后，所以 Markdown 中的图片链接也会指向 `images/` 目录。普通网页链接则已转换为绝对 URL。

## 10. 文件系统写入与目录结构

用户必须点击导出按钮触发 `showDirectoryPicker()`。这是 File System Access API 的安全要求，扩展不能在没有用户操作的情况下随意选择目录。

插件在用户选择的根目录下创建“清理后的页面标题 + 时间戳”子目录：

```text
页面标题-20260901-143000/
├── index.html
├── index.md          # 开启 Markdown 时存在
├── report.json
└── images/
    ├── photo.webp
    └── photo-2.webp
```

图片命名支持两种模式：

- 保持原名：从最终响应 URL 推导文件名，重名时追加 `-2`、`-3`。
- 顺序命名：按资源顺序使用 `1.ext`、`2.ext`、`3.ext`。

文件名中的系统非法字符会被替换，未知格式回退为 `.bin`。

## 11. 报告和失败策略

任何一张图片失败都不会中止整个任务。`report.json` 会记录：

- 原页面地址和标题。
- 截取时间与导出时间。
- 本次导出配置。
- 每项资源的 URL、元素描述、保存状态、本地文件名和失败原因。

资源状态包括成功保存、下载失败、跳过转换和转换失败。即使 WebP 转换失败，只要原始图片已经成功获取，插件仍会保存原格式文件。

## 12. 权限和浏览器兼容性

Manifest 当前使用以下主要权限：

- `activeTab`：操作用户当前激活的页面。
- `scripting`：必要时动态注入 Content Script。
- `storage`：保存导出配置。
- `<all_urls>`：允许 Content Script 匹配普通网页，并允许后台读取跨域图片。

Chrome 和 Edge 都基于 Chromium，支持 Manifest V3、扩展 Service Worker、Canvas WebP 编码和 File System Access API，因此该插件的设计同时适用于二者。

对于 `file://` 页面，`<all_urls>` 只是声明权限。用户还必须在浏览器的扩展详情页手动开启“允许访问文件网址/URL”，然后刷新本地页面；扩展无法自行开启这个安全设置。

Chrome 内置页、扩展商店等受保护页面不允许注入 Content Script，因此不能截取。

## 13. 当前边界

当前版本不处理：

- 外链 CSS 中引用的背景图。
- iframe 内部 DOM。
- Canvas 当前像素内容。
- Shadow DOM 跨边界组合选择。
- Blob URL 生命周期之外已经失效的资源。
- GIF、APNG、动画 AVIF 到动画 WebP/AVIF 的保动画转换。
- AVIF 输出编码。
- 原网页 JavaScript、交互行为和完整样式复刻。

这些限制来自浏览器安全模型、资源来源复杂性以及静态导出的产品定位，并非简单增加文件扩展名即可解决。

## 14. 构建与加载

项目使用 Vite 和 TypeScript：

```bash
npm install
npm test
npm run build
```

构建结果位于 `dist/`。在 Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions` 中开启开发者模式，选择“加载已解压的扩展”，并选择 `dist` 目录；必须选择直接包含 `manifest.json` 的目录。
